# Deep-world player-owned namespaced items — 2026-10-30

## Reproduction
With a legacy-format save containing an item stack `{id:17,key:"modded:ore/raw_cobalt",qty:3}` and a matching survival hotbar reference, `MineWorldWorldDepth.planLegacySaveMigration(save,{width:8,depth:8})` previously rejected the player inventory as an invalid stack. Furnace preflight already accepted the same bounded namespaced key. This inconsistency blocked future height migration for saves containing player-owned custom item IDs.

## Fix
Allow strict, bounded namespaced identifiers in player item stacks and direct hotbar assignments using the same namespace/path grammar and 192-character maximum as the furnace validator. Continue rejecting malformed keys, prototype names and invalid block IDs. Preserve stack identities, quantities, metadata, and Java slot references without modifying source saves.

## Verification and limits
Six Node regression tests cover successful preview, exact key identity, length bounds, malformed identifiers, hotbar validation, and parity with furnace inventories. The 384-layer Overworld remains **preview-only**; this change does not switch live terrain, rendering, collision, multiplayer or save formats. Browser smoke recordings, when generated by CI, demonstrate general gameplay and do not show a before/after deep-world migration. Resource-pack fixtures used by browser CI are independently generated, not the player's owned Minecraft pack.
